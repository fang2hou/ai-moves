# Deployment

Where the two Cloudflare environments come from, what a deploy applies, and how desk previews are produced. The step-by-step procedure is in [DEVELOPMENT.md](../DEVELOPMENT.md#deployment); operating the result is in the [operations runbook](./b4-operations-runbook.md).

## Cloudflare environments

While the repository uses the `AI News Tracker` (`ai-news-tracker`) identity, live Cloudflare Workers, D1 databases, R2 buckets, and the production domain keep their legacy Phase 1 `ai-moves-*` resource names until the infrastructure rename cutover in the [rename migration runbook](./rename-migration.md). Cloudflare Queues (`q-poll`, `q-triage`, `q-deep`, `q-deliver` and their `-dev` twins) carry no `ai-moves` prefix and stay unchanged across the cutover.

| Environment | Deployed by                                                  | Pipeline schedule                          | Workers (legacy Phase 1)                     | Storage (legacy Phase 1)              | Desk                                     |
| ----------- | ------------------------------------------------------------ | ------------------------------------------ | -------------------------------------------- | ------------------------------------- | ---------------------------------------- |
| `dev`       | Every push to `main` (or a manual `workflow_dispatch`)       | No cron; a run starts with `POST /trigger` | `ai-moves-pipeline-dev`, `ai-moves-desk-dev` | `ai-moves-dev` / `ai-moves-blobs-dev` | `ai-moves-desk-dev.fang2hou.workers.dev` |
| `prod`      | A published GitHub Release (or a manual `workflow_dispatch`) | Every 5 minutes, `*/5 * * * *`             | `ai-moves-pipeline`, `ai-moves-desk`         | `ai-moves` / `ai-moves-blobs`         | `moves.lineyahoo.dev` (custom domain)    |

`.github/workflows/deploy.yml` runs only in `fang2hou/ai-news-tracker` and, during the GitHub repository rename transition, in its former name `fang2hou/ai-moves`, so forks never deploy these Cloudflare environments. It runs `mise run check`, builds the desk, dry-runs both Worker bundles, applies pending D1 schema migrations through the recorded ledger, then deploys the pipeline and the desk. Initial rows (the published configuration, sources, and destinations) are outside `.github/workflows/deploy.yml`, which applies schema migrations only: `tools/local/seed-sql.ts` prints the seed SQL, and applying it to a fresh database is a manual initialization step. `.github/workflows/ci.yml` (job `Verify`) runs `mise run check` and `mise run build` on every pull request. `dev` and `prod` use separate D1 databases, R2 buckets, and queues (`dev` names carry a `-dev` suffix); production consumers use `max_batch_size: 1` for `q-deep` and 10 for the other queues.

## Desk pull request previews

[Desk PR Preview](../.github/workflows/preview.yml) uploads an aliased Version URL on the legacy Phase 1 `ai-moves-desk-dev` Worker for each same-repository pull request in `fang2hou/ai-news-tracker` or its former name `fang2hou/ai-moves`. The job uses the GitHub `preview` environment and a dedicated `CLOUDFLARE_PREVIEW_API_TOKEN` scoped to the Workers version and asset uploads required for previews. The workflow selects `--env dev` in `apps/api/wrangler.jsonc`, where `preview_urls: true` enables Version URLs and `DB` binds the legacy Phase 1 `ai-moves-dev` database (`5bcc51a7-b879-4a33-ab9a-7a473041125b`). Previews share the `dev` database, exclude the production Worker, domain, and database, and skip pipeline deployment and D1 migrations. See [Development](../DEVELOPMENT.md#desk-pull-request-previews) for the preview workflow and local verification commands.
