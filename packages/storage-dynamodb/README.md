# DynamoDB storage adapter

Implements the storage ports from `@ai-moves/contracts/ports/storage` on one Amazon DynamoDB table, with the semantics of the D1 adapter ([`@ai-moves/storage-d1`](../storage-d1/README.md)) and the in-memory reference ([`@ai-moves/storage/memory`](../storage/README.md)). It is the Phase 2 half of the storage seam described in [docs/portability.md](../../docs/portability.md).

| Import                                | Provides                                                                                                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@ai-moves/storage-dynamodb/api`      | `DynamoDbApi`: the slice of the DynamoDB JSON API the adapter calls; the composition root supplies a signed transport                                           |
| `@ai-moves/storage-dynamodb/dynamodb` | `createDynamoDbStorage({ api, tableName, maxAttempts? })`: every repository, with records decoded through the contracts schemas (`ROW_INVALID` on a bad record) |
| `@ai-moves/storage-dynamodb/tables`   | `STORAGE_TABLE` and `createTableInput(tableName)`: the table definition as plain data, valid as a `CreateTable` input and as `AWS::DynamoDB::Table` properties  |

- It depends on `contracts`, `kernel`, and the shared rules in `@ai-moves/storage/rules`. It has no `platform` or `raw-fetch` capability and imports no AWS SDK: the injected `DynamoDbApi` is the only way out.
- Every record stores the validated domain entity as JSON in `doc`, an optimistic version `rev`, its keys, and a few adapter attributes. Attribute values are only `S`, `N`, `BOOL`, and `NULL`.

## Key design

One table with key `pk`/`sk` and three overloaded global secondary indexes `gsi1`–`gsi3` (each `gsiNpk`/`gsiNsk`, projection `ALL`, on-demand billing). Times in sort keys are epoch milliseconds left-padded to 16 digits; `<t>#<id>` makes an `(at, id)` cursor one key comparison.

| Record                | `pk` / `sk`                                  | Index entries                                                                                                                                                                   |
| --------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source                | `SOURCES` / `<id>`                           | none: a single partition, read with a consistent query and sorted in memory                                                                                                     |
| Poll slot             | `POLLS` / `<source_id>`                      | none: a single partition                                                                                                                                                        |
| Item                  | `ITEM#<id>` / `#`                            | gsi1 `ITEM_FEED` / `<first_seen_at>#<id>` (only in `alerted`, `feed_only`); gsi2 `ITEM_SOURCE#<source>#<state>` / `<id>`; gsi3 `ITEM_STATE#<state>` / `<state_updated_at>#<id>` |
| Snapshot              | `ITEM#<item_id>` / `SNAP#<sampled_at>`       | gsi1 `SNAPSHOTS` / `<sampled_at>#<item_id>`                                                                                                                                     |
| Revision              | `ITEM#<item_id>` / `REV#<content_hash>`      | none                                                                                                                                                                            |
| Alert copy (per item) | `ITEM#<item_id>` / `ALERT#<created_at>#<id>` | none: alerts never change, so the copy written with the alert gives the per-item feed a consistent read                                                                         |
| Update ledger         | `ITEM#<item_id>` / `UPDATES`                 | none                                                                                                                                                                            |
| Analysis              | `ANALYSIS#<id>` / `#`                        | none; lease in `lease_owner`, `lease_expires_at`                                                                                                                                |
| Alert                 | `ALERT#<id>` / `#`                           | gsi1 `ALERT_FEED` / `<created_at>#<id>`; lists its `delivery_ids` and `doc_langs`                                                                                               |
| Alert document        | `ALERT#<alert_id>` / `DOC#<lang>`            | none                                                                                                                                                                            |
| Delivery              | `DELIVERY#<id>` / `#`                        | gsi2 `DELIVERY_DUE` / `<next_attempt_at or 0>#<id>` (only in `pending`, `failed_retryable`); gsi3 `DELIVERY_STATE#<state>` / `<state_updated_at>#<id>`                          |
| Send gate             | `SEND_GATE` / `#`                            | none                                                                                                                                                                            |
| Destination           | `DESTINATIONS` / `<id>`                      | none: a single partition                                                                                                                                                        |
| Audit entry           | `AUDIT#<id>` / `#`                           | gsi1 `AUDIT_LOG` / `<created_at>#<id>`                                                                                                                                          |
| Config version        | `CONFIG` / `<version>`                       | none                                                                                                                                                                            |
| Unique-key marker     | `UNIQUE#<namespace>#<sha256(value)>` / `#`   | none; `ref` names the owning record                                                                                                                                             |

Every write is a full `PutItem` built by the record's one builder, so a sparse index entry disappears as soon as the state leaves its set.

## Uniqueness and atomicity

- **Conditional updates.** A SQL `UPDATE ... WHERE state = ? AND ...` becomes a compare-and-set loop: a consistent `GetItem`, the predicate evaluated in TypeScript with the shared rules, then a write conditioned on `rev`. A write that loses to any other write re-reads and re-evaluates, so an unrelated concurrent change (an `upsertObserved` advancing `last_seen_at`) never makes a `transition` fail; only a predicate that is false after a fresh read does. After `maxAttempts` (default 8) lost rounds the call fails with `STORAGE_UNAVAILABLE`.
- **Unique keys.** Source `key`, item `external_key`, the analysis key `(item_id, stage, input_hash, prompt_version, lang)`, alert `alert_key`, delivery `idempotency_key`, and destination `name` each have a marker record written in the same `TransactWriteItems` as the row, both conditioned on `attribute_not_exists`. Markers key on a SHA-256 digest because natural keys can exceed DynamoDB's 2048-byte partition key limit. A failed condition is a replay when the marker exists after a consistent re-read, and `STATE_CONFLICT` otherwise (the id belongs to another row).
- **Alerts with deliveries.** The alert, its key marker, its per-item copy, its documents, and every delivery with its idempotency marker are one transaction, so a failed write leaves none of them visible. Within the batch a repeated idempotency key is skipped and a repeated id is `STATE_CONFLICT`; a delivery id or idempotency key already stored for another alert is `STATE_CONFLICT`, never a replay. The D1 adapter surfaces that collision as `STORAGE_UNAVAILABLE` (retryable) through its batch failure; here it is permanent, so the consumer acknowledges the job instead of retrying it. A transaction holds at most 100 items, so an insert carries at most `(100 - 3 - documents) / 2` deliveries (47 with three documents); a larger batch fails with `INPUT_INVALID` before anything is sent.
- **Send claims.** `claimForSend` reproduces the D1 statement: the eligibility predicate, then `update_limit` (for an `update` alert, at least `maxUpdatesPerItem` other `update` alerts of the item hold a live reservation), then `rate_limit` (with an interval, another alert's live delivery is `sending`, or became `sent` or `unknown` after the cutoff). The inputs are kept in strongly read records rather than indexes: the singleton send gate holds the `sending` reservations and, per alert, the latest time a live delivery became `sent` or `unknown` for the two most recent alerts (those states are terminal, so two suffice); the per-item update ledger counts live reservations per `update` alert. Each delivery carries its alert's `kind` and `item_id` from insert time. A claim writes the delivery, the gate, and the ledger in one transaction conditioned on all three versions; a suppression writes the delivery with a `ConditionCheck` on the versions it decided from. `transition` releases the reservation in the same way unless the target is `sent` or `unknown`.
- **Configuration.** `config.publish` appends `max + 1` under `attribute_not_exists` and retries on a lost race. `admin.publishConfig` writes version `expectedVersion + 1`, a `ConditionCheck` that `expectedVersion` exists, and the audit entry in one transaction; versions are contiguous, so this is the SQL `expectedVersion = MAX(version)`. A failed condition (version moved or audit id taken) returns `null`.
- **Destination patches.** `admin.patchDestination` writes the destination under its version and the audit entry under `attribute_not_exists` in one transaction; a taken audit id or a missing destination returns `false`.

## Errors

`AppError` passes through. A rejected transport, any service error (throttling, `5xx`, `ValidationException`, `TransactionConflictException`), a transaction cancelled for a reason other than a failed condition, and exhausted retries are `STORAGE_UNAVAILABLE`, as in the D1 adapter. A record over the item size limit and a transaction over 100 items are detected before sending and fail with `INPUT_INVALID`, because retrying them cannot succeed.

## Known limits

- **Eventual consistency.** Index reads may lag a write by a short interval: the item and alert feeds, `items.listBySourceAndStates`, `items.listStale`, `deliveries.listDue`, `deliveries.listStale`, `audit.listRecent`, and the candidate list of `snapshots.deleteBefore`. Each caller either tolerates a stale page or re-checks with a conditional write. Every correctness decision (claims, transitions, replays, `listByAlert`, the per-item alert feed, snapshot and revision lists, configuration) reads the base table with strong consistency.
- **Item size.** A record is limited to 400 KB, so alert documents are stored one record per language rather than as one array.
- **Hot keys.** The send gate is written by every live claim and release, and the feed, due, and audit index partitions are single values. At the project's volume (tens of deliveries per hour) this is far below per-partition limits; a much higher send rate would need the gate sharded.
- **Differences from SQL.** Foreign keys are not enforced (as in the memory adapter). Ties in `deleteBefore` are broken by item id instead of SQLite `rowid`. Ids compare by bytes, which matches SQLite; the memory adapter's `localeCompare` differs only for mixed-case ids.
- **Data migration.** Copying rows from D1 must also build the markers, the per-item alert copies, the send gate, and the update ledgers from the rows with `live_send_reserved = 1`.
